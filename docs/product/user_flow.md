# 유저 플로우 (User Flow) — just-make-it

> 대상: 소상공인 (비전문가)  
> 목표: “광고 이미지 만들기”가 막막하지 않도록, **선택지를 주고 기본값을 강하게** 제공한다.  
> 상태: 초안 (PM 작성). 팀 리뷰 후 확정.

---

## 1. 핵심 원칙

1. **목적(어디에 쓸지)을 먼저** 묻는다. 기술 용어보다 “인스타 피드”, “스마트스토어”처럼 실제 쓰는 말로.
2. **입력은 최소화**한다. 가게/상품 이름 + 핵심 메시지 정도면 충분.
3. **생성 방식은 기본값을 강하게** 주고, 고급 옵션은 접어둔다.
4. **결과 확인 → 쉬운 수정** 경로를 반드시 제공한다.
5. 실패/대기 시에도 “지금 처리 중이에요 / 조금 더 걸릴 수 있어요”처럼 친절하게 안내한다. (로컬 GPU busy → OpenAI fallback은 유저에게 기술 상세를 노출하지 않는다.)

---

## 2. 전체 플로우 개요

```
[시작]
   │
   ▼
① 목적(매체) 선택
   │
   ▼
② 기본 정보 입력 (+ 참고 이미지 선택)
   │
   ▼
③ 생성 방식 선택  (기본값: 빠른 생성)
   │
   ▼
④ 생성 요청 → 대기/진행 표시
   │
   ▼
⑤ 결과 확인
   │
   ├─ 만족 → 다운로드 / 링크 복사 / 저장
   │
   └─ 수정 → 간단한 수정 옵션 or 프롬프트 재작성 → ④로
```

---

## 3. 단계별 상세

### ① 목적(매체) 선택

유저가 가장 먼저 보는 화면.

| 선택지 (예시)              | 설명 (유저에게 보이는 문구)                  | 내부적으로 활용할 힌트                  |
|---------------------------|---------------------------------------------|----------------------------------------|
| 인스타그램 피드/스토리    | 인스타에 올릴 정사각형·세로 이미지          | 비율 1:1 또는 9:16, 텍스트 가독성 중시 |
| 스마트스토어 / 쿠팡 등    | 상품 상세·썸네일용                          | 상품 중심, 깔끔한 배경, 가격/할인 강조 |
| 유튜브 썸네일             | 클릭을 유도하는 강한 썸네일                 | 16:9, 큰 텍스트, 대비 강하게           |
| 카카오톡 / 문자 홍보      | 메시지에 첨부할 이미지                      | 세로형 또는 정사각, 짧은 문구          |
| 자유롭게 만들기           | 원하는 대로 직접 설정                       | 기본 비율 선택 UI 제공                 |

- 기본 선택: 없음 (반드시 하나 고르게)
- 선택 후 “이 용도에 맞는 추천 설정이 적용됩니다” 정도의 안내

### ② 기본 정보 입력

필수 + 선택으로 나눈다.

**필수**
- 가게/상품 이름 (또는 브랜드명)
- 핵심 메시지 / 키워드 (예: “신메뉴 출시”, “주말 20% 할인”, “오픈 이벤트”)

**선택**
- 참고 이미지 업로드 (상품 사진, 로고 등) — 최대 1~2장
- 추가 설명 (자유 텍스트, 짧게)
- 원하는 분위기/스타일 (예: 밝고 경쾌, 고급스러움, 따뜻함) — 칩(Chip) 형태로 제공 권장

**홍보 문구 도우미 (추천 기능)**
- “핵심 메시지만 입력하면 홍보 문구 3개를 자동으로 제안” 버튼
- 제안된 문구 중 하나를 선택하거나 수정해서 사용
- 이 단계에서 이미 텍스트가 준비되면 이후 생성 품질이 올라간다.

### ③ 생성 방식 선택 → **삭제 (2026-10-20)**

- 이미지는 항상 글자 없이 만들고, 문구는 웹에서 이미지 위에 얹는다 (`api_spec.md` 5장 "글자 처리")
- 유저는 방식을 고르지 않는다. 결과 화면에서 글자 내용·위치(위/가운데/아래)·크기를 바로 고치고, 재생성 없이 반영된다
- 스마트스토어·쿠팡은 ②에서 **대표 이미지 1장 / 상세페이지** 중 고른다

### ④ 생성 요청 및 대기

- 버튼: “이미지 만들기”
- 진행 상태:
  - 즉시 응답 가능하면 바로 결과
  - 대기 시: “이미지를 만들고 있어요. 보통 10~30초 걸려요.”
  - Fallback 발생 시에도 동일한 UX 유지 (기술 상세 숨김)
- 에러 시: “잠시 후 다시 시도해 주세요” + 재시도 버튼

### ⑤ 결과 확인 & 후속 액션

**결과 화면**
- 생성된 이미지 크게 표시
- 사용한 목적/메시지 요약 표시 (수정 시 참고용)

**주요 액션**
- 다운로드 (PNG/JPG)
- 링크 복사 (결과 화면 영구 링크)
- “다시 만들기” (같은 설정으로 재생성)
- “조금 수정하기”
  - 예시 칩: “글자 더 크게”, “더 밝게”, “배경 단순하게”, “텍스트 위치 바꾸기” 등
  - 또는 프롬프트 직접 수정 후 재생성

**만족하지 않을 때**
- 같은 설정으로 한 번 더 생성
- 목적/메시지/방식 중 일부만 바꿔서 재시도
- (향후) 간단한 캔버스 편집으로 이동

## 4. MVP 범위 제안

| 포함 (v1)                          | 보류 (v1.1 이후)                     |
|------------------------------------|--------------------------------------|
| 목적 선택 5종                      | 고도화된 캔버스 편집기               |
| 필수 정보 + 참고 이미지 1장        | 여러 장 일괄 생성                    |
| 빠른 생성 (기본) + 템플릿 일부     | 브랜드 키트(로고/컬러) 저장          |
| 결과 다운로드 + 링크 복사          | 히스토리/마이페이지 고도화           |
| 간단한 수정 칩 + 재생성            | A/B 테스트용 변형 생성               |
| 로컬 GPU + OpenAI Fallback         | 유저별 사용량/결제 연동 (필요 시)    |

---

## 5. 성공 지표 (초안)

- 목적 선택 → 생성 완료까지 이탈률
- 생성 완료 후 다운로드/링크 복사 비율
- “다시 만들기” / “수정하기” 사용 비율
- 평균 생성 시간 (로컬 vs Fallback)
- (정성) 소상공인 인터뷰에서 “혼자 할 수 있을 것 같다”는 응답

---

## 6. 미결 사항 / 다음에 정할 것

- [ ] 목적별 기본 이미지 비율·해상도 확정
- [ ] 템플릿을 몇 개부터 제공할 것인가
- [ ] 참고 이미지 업로드 시 사용 방식 (IP-Adapter, 단순 참조 등) — 모델 파트와 협의
- [ ] 비로그인 사용 허용 여부 / 일일 생성 제한
- [ ] 결과물 워터마크 여부
- [ ] 모바일 우선인지, 데스크톱 우선인지 (반응형 수준)
