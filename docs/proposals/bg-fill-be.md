# 제안: 배경 채우기 BE 연동 (FE 배경 지우기 이후)

- 현재(FE): 상품 사진 배경을 브라우저에서 지우고(BiRefNet_lite 512, MIT, HF에서 직접 받음) 단색으로 채운 뒤 참고 사진으로 `/generate`에 보냄. 서버 변경 없음.
- 다음 단계: AI가 만든 장면 배경("대리석 테이블, 아침 햇살") 위에 누끼 상품을 얹기.

**권장 흐름**
1. FE가 누끼 PNG(투명 배경)를 보관한 채 서버에 **배경만** 생성 요청 (상품 없는 빈 장면, 글자 없음).
2. 서버는 기존 생성 경로 그대로 `background_url`을 돌려줌. 상품을 그리지 않으므로 Gemma 품목 묘사 단계 생략 가능.
3. FE canvas가 배경 + 누끼 상품 + 그림자 + 글자를 합성 (`TextCanvas` 흐름 재사용). 상품 픽셀이 100% 보존됨.

**서버에 필요한 것 (서빙·모델 담당 검토)**
- `/generate` 입력에 "배경만" 의도를 담을 방법 (예: `output: "background"`) → 합의 후 PM이 `api_spec.md`에 반영.
- core 프롬프트: 상품 없이 장면만, 가운데 아래쪽을 비워 두는 구도. klein으로 충분(참고 이미지 없음 → VRAM 추가 부담 없음).
- 한도·비용: 기존 일일 생성 한도에 그대로 포함. OpenAI Fallback 때도 장당 약 $0.014로 동일.

**대안과 판단**
- 누끼를 참고 이미지로 넣어 장면째 생성(flare `images.edit`): 조명은 자연스럽지만 상품 모양이 바뀔 수 있고 비용 발생 → 보류.
- 휴대폰에서 누끼 실패 시 서버 처리: VM RAM 16GB·GPU 상주 모델과 경합 → 지금은 "원래 사진 쓰기" 안내로 충분.
